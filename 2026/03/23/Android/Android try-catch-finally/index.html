📖 try-catch-finally 核心讲解

try-catch-finally 是 Java/Android 中处理异常（Exception） 的核心语法，作用是捕获程序运行中可能出现的错误、保证程序不崩溃，同时执行必须完成的收尾操作（如关闭资源）。

用通俗的话讲：

  • try：“尝试” 执行一段可能出问题的代码；

  • catch：如果 try 里的代码出了问题，就 “捕获” 这个问题并处理；

  • finally：不管 try 里的代码是否出错，最终 “必须” 执行的代码（收尾操作）。

一、基础语法结构

关键规则：

  1. try 是必须的，catch 和 finally 至少要有一个（可以 try-catch、try-finally、try-catch-finally）；

  2. 多个 catch 时，异常类型要从小到大（子类异常在前，父类异常在后，如 NullPointerException 在前，Exception 在后）；

  3. finally 即使遇到 return 也会执行（唯一例外：System.exit(0) 终止虚拟机）。

二、逐部分拆解（结合 Android 场景示例）

1. try 块：执行风险代码

存放 “可能出错” 的代码，比如：

  • 数据类型转换（如 String 转 int）；

  • 文件 / 数据库操作；

  • 网络请求；

  • 访问空对象的属性 / 方法。

2. catch 块：捕获并处理异常

try 里的代码抛出异常时，会跳转到匹配的 catch 块执行，避免程序崩溃。

3. finally 块：执行收尾操作

无论 try 是否出错、catch 是否执行，finally 都会执行，核心用于释放资源（Android 中高频场景：关闭 Cursor、关闭文件流、注销广播、关闭数据库连接）。

三、常见使用场景（Android 开发高频）

场景 1：处理空指针异常（NullPointerException）

场景 2：文件操作（关闭文件流）

场景 3：广播注销（避免内存泄漏）

四、特殊情况：finally 与 return 共存

即使 try 或 catch 里有 return，finally 仍会执行（执行顺序：先执行 finally，再返回）。

⚠️ 注意：不要在 finally 里写 return，会覆盖 try/catch 的返回值，导致逻辑混乱！

五、核心总结

部分 作用 必选？ 高频使用场景
try 执行可能抛出异常的代码 ✅ 是 数据转换、文件 / 数据库操作、网络请求
catch 捕获异常并处理（避免程序崩溃） ❌ 可选 空指针、数字格式、IO 异常处理
finally 执行必须完成的收尾操作 ❌ 可选 关闭资源（Cursor / 文件流 / 广播）、释放内存
