Android 子线程

🚀 Android 子线程核心讲解：作用、方法与实战

在 Android 中，子线程（Worker Thread） 是相对于「主线程（UI Thread）」的概念 —— 主线程负责处理 UI 渲染、用户交互（如点击事件），子线程负责执行「耗时操作」（如网络请求、数据库读写、文件处理），核心目的是 避免阻塞主线程，防止应用 ANR（应用无响应）。

简单说：UI 相关的操作必须在主线程，耗时操作必须在子线程。

一、为什么需要子线程？（Android 主线程规则）

Android 规定：

  1. 主线程（UI 线程）的任务执行时间不能超过 5 秒（否则触发 ANR）；

  2. 网络请求、数据库查询、大文件读写等耗时操作，必须放在子线程；

  3. 子线程 不能直接操作 UI（如更新 TextView 文本、修改按钮状态），否则会抛出 CalledFromWrongThreadException。

典型场景（必须用子线程）：

  • 从网络加载图片 / 数据（如请求接口）；

  • 批量操作数据库（如导入 1000 条用户数据）；

  • 读取 / 写入大文件（如游戏资源、视频）；

  • 复杂计算（如数据加密、排序）。

二、Android 中子线程的 5 种核心实现方法（从简单到主流）

方法 1：直接继承 Thread 类（最基础）

通过继承 Thread 并重写 run() 方法，run() 里的代码就是子线程要执行的逻辑。

⚠️ 注意：

  • 启动线程用 start()，会触发 run() 执行（底层调用 native 方法创建线程）；

  • 直接调用 run() 不会创建新线程，只是普通方法调用，仍在主线程执行。

方法 2：实现 Runnable 接口（解耦更强）

Runnable 是线程任务接口，只定义 run() 方法，避免了 Thread 类的单继承限制（更灵活）。

方法 3：使用 AsyncTask（Android 原生，适合简单 UI 交互）

AsyncTask 是 Android 封装的「轻量级异步工具」，专门解决「子线程执行耗时操作 + 主线程更新 UI」的场景，内部封装了线程池和 Handler。

核心方法（生命周期）：

  • onPreExecute()：主线程执行，任务开始前的准备（如显示加载对话框）；

  • doInBackground(Params...)：子线程执行，耗时操作核心（不能操作 UI）；

  • onPostExecute(Result)：主线程执行，任务完成后更新 UI（接收 doInBackground 的返回值）；

  • onProgressUpdate(Progress...)：主线程执行，实时更新进度（如下载进度条）。

  • AsyncTask 在 Android 11（API 30）后被标记为过时（@Deprecated），原因是容易引发内存泄漏（若持有 Activity 引用），复杂场景推荐用 Coroutine 或 RxJava；

  • 不能在 doInBackground 中直接操作 UI，必须通过 publishProgress 或 onPostExecute。

方法 4：使用 HandlerThread（循环子线程，适合持续任务）

HandlerThread 是 Thread 的子类，内部封装了 Looper 和 MessageQueue，可以通过 Handler 向子线程发送消息，实现「循环执行任务」（如后台轮询、持续数据同步）。

核心优势：

  • 单线程循环，避免多线程并发问题；

  • 可通过 Handler 灵活发送任务，无需重复创建线程。

Coroutine（协程）是 Google 推荐的现代化异步方案，基于 Kotlin 语法，比 AsyncTask 更简洁、更安全，支持取消、异常处理、生命周期绑定。

  • 语法简洁，无需手动管理线程和 Handler；

  • 自动切换线程（Dispatchers.IO 子线程，Dispatchers.Main 主线程）；

  • 支持生命周期绑定（如 viewModelScope，避免内存泄漏）。

三、子线程与主线程的通信（关键！）

子线程不能直接操作 UI，必须通过「通信机制」通知主线程更新 UI，常用 3 种方式：

1. Handler（最基础）

通过 Handler 发送 Message 或 Runnable 到主线程的消息队列，主线程的 Looper 处理消息并更新 UI。

2. AsyncTask 的 onPostExecute/publishProgress

如方法 3 所示，doInBackground 执行完后，结果自动传递到 onPostExecute（主线程），无需手动处理通信。

3. runOnUiThread（Activity 内置方法）

Activity 提供的便捷方法，直接将 Runnable 切换到主线程执行，本质是通过 Handler 实现。

1. 避免内存泄漏

3. 子线程不能操作 UI 的原因

Android UI 控件是非线程安全的，多个线程同时操作 UI 会导致界面错乱；主线程的 Looper 会串行处理 UI 事件，确保 UI 操作的原子性。

五、方法对比与选型建议

方法 优点 缺点 适用场景
Thread 简单直观 无返回值、难管理、频繁创建耗资源 简单一次性耗时操作
Runnable 解耦强、可复用 无返回值、需手动管理线程 多线程共享任务逻辑
AsyncTask 内置 UI 回调、进度更新 过时、易内存泄漏、不适合复杂场景 Android 低版本（API < 30）简单场景
HandlerThread 循环任务、单线程安全 不适合并行任务 后台轮询、持续数据同步
Coroutine 简洁、安全、支持生命周期绑定 Java 需配合 Kotlin、学习成本 现代 Android 开发（推荐）

新手选型：

  • 简单场景（如单次数据库查询）：用 Thread + Runnable；

  • 需要更新 UI 进度（如文件下载）：用 AsyncTask（低版本）或 Coroutine（高版本）；

  • 持续任务（如后台轮询）：用 HandlerThread；

  • 新项目 / 高版本（API ≥ 30）：优先用 Coroutine。

总结

子线程的核心作用是「承载耗时操作，保护主线程不阻塞」，Android 提供了多种实现方式，核心要解决两个问题：

  1. 耗时操作放在子线程执行；

  2. 子线程与主线程的安全通信（更新 UI）。
