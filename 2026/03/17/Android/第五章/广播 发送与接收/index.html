广播发送与接收

一、广播（Broadcast）是什么？

广播是 Android 中的一种 跨组件通信机制，类似现实中的 “电台广播”：

  • 发送者（广播源）：发出特定事件的组件（如系统、Activity、Service）。

  • 接收者（BroadcastReceiver）：监听并响应广播的组件（需注册才能接收）。

  • 核心作用：传递全局事件（如系统启动完成、网络状态变化、电量低提示），实现组件间解耦通信。

二、广播的分类（核心！）

根据发送方式和特性，广播分为 3 类，实际开发中用途不同：

类型 特点 发送方式 适用场景
标准广播（Normal Broadcast） 异步、无序、效率高，无法拦截 sendBroadcast(Intent) 无需优先级、不担心拦截的事件（如通知更新）
有序广播（Ordered Broadcast） 同步、有序（按优先级），可拦截、修改数据 sendOrderedBroadcast(Intent, receiverPermission) 需要按顺序处理的事件（如短信接收、电话来电）
本地广播（Local Broadcast） 仅本应用内传播，安全、高效，避免跨应用攻击 LocalBroadcastManager.sendBroadcast(Intent) 应用内部组件通信（如 Activity 向 Service 发消息）

注意：Android 8.0（API 26）后，

静态注册的广播接收器（除少数系统广播外）无法接收隐式广播

，推荐使用动态注册或显式广播。

三、广播接收者（BroadcastReceiver）的创建

无论哪种广播，都需要先创建接收者（继承 BroadcastReceiver），重写 onReceive(Context context, Intent intent) 方法（核心：接收广播后的逻辑）。

1. 基础接收者（通用模板）

关键注意点：

  • onReceive() 运行在 主线程，禁止耗时操作（如网络请求、循环）。

  • 接收者生命周期极短：onReceive() 执行完后，接收者实例会被系统回收。

  • 不能在接收者中创建对话框（需加 TYPE_SYSTEM_ALERT 权限，且体验差），推荐用 Notification 提示。

四、广播的注册方式（必须！否则接收不到）

广播接收者需要 “注册” 到系统，才能监听广播。注册分为 静态注册 和 动态注册，各有适用场景。

1. 静态注册（AndroidManifest.xml 中声明）

  • 特点：应用未启动也能接收广播（如系统启动广播），但 8.0 后受限。

  • 步骤：

    （1）在 AndroidManifest.xml 中添加 > 标签：

  • 静态注册无法接收 隐式广播（即 Intent 未指定接收者包名的广播）。

  • 解决方案：发送广播时指定接收者包名（显式广播），或改用动态注册。

import androidx.appcompat.app.AppCompatActivity;

import android.content.IntentFilter;

import android.os.Bundle;

public class MainActivity extends AppCompatActivity {

private MyBroadcastReceiver myReceiver;

@Override

protected void onCreate(Bundle savedInstanceState) {

   super.onCreate(savedInstanceState);

   setContentView(R.layout.activity_main);

   // 1. 创建接收者实例

   myReceiver = new MyBroadcastReceiver();

   // 2. 创建 IntentFilter，指定要接收的广播 Action

   IntentFilter intentFilter = new IntentFilter();

   intentFilter.addAction("com.example.MY_CUSTOM_ACTION"); // 自定义广播

   intentFilter.addAction(Intent.ACTION_NETWORK_STATE_CHANGED); // 系统广播：网络状态变化

   // 3. 注册广播（核心方法：registerReceiver）

   registerReceiver(myReceiver, intentFilter);

}

@Override

protected void onDestroy() {

   super.onDestroy();

   // 4. 必须取消注册！否则会导致内存泄漏（接收者持有 Activity 引用）

   unregisterReceiver(myReceiver);

}

}

// 1. 创建 Intent，指定广播 Action（需与接收者的 Action 一致）

Intent intent = new Intent(“com.example.MY_CUSTOM_ACTION”);

// 2. （可选）携带数据

intent.putExtra(“key_msg”, “这是一条标准广播”);

// 3. （8.0+ 必需）指定接收者包名（显式广播，避免静态接收者收不到）

intent.setPackage(getPackageName()); // 本应用内接收者

// 若要发送给其他应用，指定对方应用包名：intent.setPackage(“com.other.app”);

// 4. 发送标准广播

sendBroadcast(intent);

public class HighPriorityReceiver extends BroadcastReceiver {

@Override

public void onReceive(Context context, Intent intent) {

   // 1. 获取原始数据

   String data = intent.getStringExtra("key_data");

   Toast.makeText(context, "高优先级接收者：" + data, Toast.LENGTH_SHORT).show();

   // 2. 修改数据（后续接收者收到的是修改后的数据）

   intent.putExtra("key_data", "修改后的数据");

   // 3. 拦截广播（后续低优先级接收者收不到）

   abortBroadcast();

}

}

import androidx.localbroadcastmanager.content.LocalBroadcastManager;

import android.content.Intent;

// 发送本地广播（仅本应用内接收者能收到）

public void sendLocalBroadcast() {

Intent intent = new Intent(“com.example.LOCAL_ACTION”);

intent.putExtra(“key_msg”, “这是本地广播”);

// 核心：通过 LocalBroadcastManager 发送，而非 Context

LocalBroadcastManager.getInstance(this).sendBroadcast(intent);

}

// 本地广播的动态注册（接收者需通过 LocalBroadcastManager 注册）

IntentFilter filter = new IntentFilter(“com.example.LOCAL_ACTION”);

LocalBroadcastManager.getInstance(this).registerReceiver(localReceiver, filter);

public class NetworkReceiver extends BroadcastReceiver {

@Override

public void onReceive(Context context, Intent intent) {

   if (intent.getAction().equals(Intent.ACTION_NETWORK_STATE_CHANGED)) {

       // 判断网络是否可用（需添加权限：android.permission.ACCESS_NETWORK_STATE）

       ConnectivityManager cm = (ConnectivityManager) context.getSystemService(Context.CONNECTIVITY_SERVICE);

       NetworkInfo info = cm.getActiveNetworkInfo();

       if (info != null && info.isConnected()) {

           Toast.makeText(context, "网络已连接", Toast.LENGTH_SHORT).show();

       } else {

           Toast.makeText(context, "网络已断开", Toast.LENGTH_SHORT).show();

       }

   }

}

}

### 七、广播使用的避坑指南



1. **避免 ANR**：`onReceive()` 中不能做耗时操作（>10 秒），需耗时则启动 Service 处理。

2. **8.0+ 静态注册限制**：静态接收者只能接收显式广播或少数系统广播（如 `ACTION_BOOT_COMPLETED`），优先用动态注册。

3. **内存泄漏**：动态注册必须取消注册（`unregisterReceiver()`），静态注册无需（系统自动管理）。

4. **权限控制**：发送有序广播时可指定权限，接收者需声明对应权限才能接收；接收其他应用的广播时，需对方发送时允许。

5. **本地广播优先**：应用内部通信优先用本地广播（`LocalBroadcastManager`），避免跨应用安全问题。

6. **广播数据大小限制**：Intent 携带的数据不能过大（建议 <100KB），否则可能导致传输失败或内存问题。

### 八、广播与其他通信方式的对比



| 通信方式                 | 适用场景         | 优势            | 劣势            |
| -------------------- | ------------ | ------------- | ------------- |
| 广播（Broadcast）        | 全局事件通知、跨组件通信 | 解耦强、简单易用      | 效率一般、无法直接返回结果 |
| ViewModel + LiveData | 应用内组件共享数据    | 生命周期感知、无内存泄漏  | 仅应用内使用、不能跨进程  |
| EventBus             | 复杂项目跨组件通信    | 代码简洁、支持多种线程模式 | 依赖第三方库、调试难度大  |
| Intent               | 组件间跳转 + 数据传递 | 原生支持、简单直接     | 数据大小受限、仅单次传递  |
