LitePal

一、LitePal 核心概念

LitePal 是 Android 平台的 开源 ORM（对象关系映射）框架，核心作用是将 Java 对象与 SQLite 数据库表映射，无需编写 SQL 语句即可完成数据库操作，大幅简化 SQLite 开发。

核心优势：

  • 零 SQL 语句：通过 Java API 操作数据库，无需手动编写 SQL。

  • 自动建表 / 升级：根据实体类自动生成表结构，支持数据库版本升级。

  • 轻量级：体积小（约 100KB），集成简单，学习成本低。

  • 支持关联关系：一对一、一对多、多对多（需手动配置）。

  • 兼容 SQLite：可混合使用原生 SQL 语句（灵活扩展）。

适用场景：

  • 结构化数据存储（如用户列表、商品信息、历史记录）。

  • 不需要复杂 SQL 逻辑的中小型应用。

  • 想简化 SQLite 操作、提升开发效率的场景。

六、LitePal 避坑指南

  1. 实体类必须继承 LitePalSupport：LitePal 3.x 不再支持 DataSupport，继承错误会导致无法操作数据库。

  2. 必须提供 getter/setter 方法：LitePal 通过反射获取 / 设置字段值，缺少 getter/setter 会导致数据读写失败。

  3. 主键字段规范：默认主键为 long 类型的 id，自增（无需手动设置），若自定义主键，需添加 @PrimaryKey 注解。

  4. 数据库升级注意事项：

  • 仅新增字段或新增实体类时，递增版本号即可自动升级。

  • 修改字段类型、删除字段时，自动升级无效，需手动执行 SQL 或强制重建表（数据会丢失）。

  1. 避免在主线程执行耗时操作：大量数据的插入、查询、更新操作会阻塞主线程，导致 UI 卡顿，建议放在子线程中执行（如用 AsyncTask、Thread 或 Coroutine）。

  2. 字段类型兼容问题：

  • SQLite 不支持 boolean 类型，LitePal 会自动将 boolean 转换为 int（1=true，0=false）。

  • Date 类型会自动转换为时间戳（long）存储，查询时自动转换回 Date。

  1. 外部存储权限：如果在 litepal.xml 中设置 external"，需申请外部存储读写权限（Android 6.0+ 需动态申请）。

  2. Cursor 必须关闭：执行原生 SQL 查询返回的 Cursor，必须手动关闭，避免资源泄漏。

七、LitePal 与其他数据库框架对比

框架 优势 劣势 适用场景
LitePal 零 SQL、集成简单、轻量级 复杂查询支持有限、关联关系需手动配置 中小型应用、简单结构化数据
Room 官方推荐、编译时校验、支持协程 / Flow 学习成本略高、需注解配置 结构化数据、复杂查询、大型应用
GreenDAO 性能高、支持复杂关联、缓存机制 集成步骤多、体积较大 高性能需求、复杂数据关系
SQLite 原生支持、灵活度极高 需手动写 SQL、操作繁琐 复杂 SQL 逻辑、底层定制需求
