Android Activity 生命周期

一、生命周期核心定义

1. 通俗理解

Activity 生命周期是指 Activity 从创建 → 运行 → 暂停 → 停止 → 销毁 的完整生命周期过程，系统会在不同阶段自动调用对应的生命周期方法，开发者可重写这些方法完成「资源初始化 / 释放」「页面状态管理」等操作。

2. 教材官方定义

Activity 生命周期由 Android 系统管理，遵循 “状态机” 规则，每个状态对应固定的回调方法，保证 Activity 与系统资源（内存、CPU、屏幕显示）的合理交互，是 Android 四大组件生命周期的核心。

二、7 个核心生命周期方法（教材重点）

方法名 触发时机（教材描述） 核心作用（教材要求掌握） 执行次数
onCreate() Activity 首次创建时触发（仅初始化阶段） ① 加载布局（setContentView()）；② 绑定控件（findViewById()）；③ 初始化数据 / 监听器；④ 恢复临时数据（savedInstanceState） 仅 1 次
onStart() Activity 从「不可见 → 可见」（未交互） 界面可见性相关操作（如刷新页面显示） 可多次
onResume() Activity 从「可见 → 可交互」（前台运行） 开启可交互资源：动画、定时器、传感器、音视频播放 可多次
onPause() Activity 从「可交互 → 不可交互」（切后台 / 来电话） ① 暂停可交互资源；② 保存临时数据（如输入框内容）；③ 禁止耗时操作（系统等待此方法完成） 可多次
onStop() Activity 从「可见 → 完全不可见」（被新 Activity 覆盖 / 切后台） 释放非核心可见资源：停止界面刷新、关闭弹窗 可多次
onRestart() Activity 从「完全不可见 → 即将可见」（切后台后切前台） 重启前的准备操作（如重新加载临时数据） 可多次
onDestroy() Activity 销毁前触发（返回键 / 系统回收） 释放所有资源：关闭数据库 / 网络请求、解绑监听器、释放图片资源（避免内存泄漏） 仅 1 次

教材强调的核心特性

  1. onCreate() + onDestroy()：生命周期 “首尾” 方法，仅执行 1 次，负责全局资源的初始化与释放；

  2. onResume() + onPause()：高频触发方法，负责可交互资源的启停，是性能优化的核心；

  3. onPause() 执行时限：系统最多等待 500ms，耗时操作会导致 APP 卡顿 / 被杀死。

三、3 个典型生命周期场景（教材必讲）

场景 1：首次启动 Activity（完整创建流程）

操作：桌面点击 APP 图标 → 启动 MainActivity

方法执行顺序：onCreate() → onStart() → onResume()

教材备注：此流程完成后，Activity 进入「活动状态（Resumed）」，可与用户交互。

场景 2：切后台 → 切前台（暂停 - 恢复流程）

  • 切后台（按 Home 键）：onPause() → onStop()（进入「停止状态（Stopped）」，不可见但未销毁）；

  • 切前台（重新打开 APP）：onRestart() → onStart() → onResume()（恢复「活动状态」）。

场景 3：返回键退出 Activity（销毁流程）

操作：按返回键关闭 Activity

方法执行顺序：onPause() → onStop() → onDestroy()

教材备注：销毁后 Activity 实例被回收，再次打开会重新执行onCreate()。

补充场景（教材扩展）：屏幕旋转 / 内存不足

执行顺序：onPause() → onStop() → onDestroy()（销毁旧实例） → onCreate() → onStart() → onResume()（重建新实例）；

教材要求：需通过 savedInstanceState 保存临时数据（如输入框内容），避免数据丢失。

四、生命周期核心原则（教材强调）

1. 资源配对原则（核心）

  • onCreate() 初始化的资源 → onDestroy() 释放（如数据库连接、全局监听器）；

  • onResume() 开启的资源 → onPause() 暂停 / 释放（如定时器、动画）；

    → 违反此原则会导致内存泄漏，APP 越用越卡。

2. 状态不可逆原则

生命周期方法按 “创建→运行→销毁” 单向执行，不可反向触发（如onDestroy()后不会再执行onRestart()）。

3. 系统回收规则

当内存不足时，系统优先回收「Stopped 状态」的 Activity，回收前会触发onSaveInstanceState()保存临时数据。

五、实战注意事项（教材实战部分）

1. 重写方法规范

  • 必须调用父类方法（如super.onCreate(savedInstanceState)），否则会抛出运行时异常；

  • 避免在onCreate()中执行耗时操作（如网络请求），会导致页面启动卡顿。

六、常见误区（教材易错点）

  1. 认为onStop()是销毁：onStop()仅表示页面不可见，onDestroy()才是真正销毁；

  2. 在onPause()中做耗时操作：如网络请求、数据库批量操作，会导致切后台卡顿；

  3. 忘记释放资源：如onDestroy()中未关闭定时器，导致内存泄漏；

  4. 忽略savedInstanceState：屏幕旋转后数据丢失，是新手高频错误。

七、核心总结（教材考点）

  1. Activity 生命周期 7 个方法按 “创建 - 可见 - 交互 - 暂停 - 停止 - 重启 - 销毁” 执行，onCreate()/onDestroy()仅执行 1 次；

  2. 资源管理遵循 “配对原则”：可交互资源在onResume()开启、onPause()关闭，全局资源在onCreate()初始化、onDestroy()释放；

  3. 屏幕旋转 / 内存不足会触发 Activity 重建，需通过savedInstanceState保存临时数据。
