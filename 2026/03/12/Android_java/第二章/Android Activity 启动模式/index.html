Android Activity 启动模式

Activity 启动模式是 Android 系统用于管理 Activity 栈（Task 栈）、控制页面跳转 / 复用行为的核心机制，解决 “重复创建 Activity 实例、返回栈混乱、资源浪费” 等问题。以下是教材级的完整笔记，涵盖核心概念、4 种启动模式及实战场景。

一、核心基础：Activity 栈（Task 栈）

1. 通俗理解

Activity 栈（Task 栈）是系统为每个 APP 分配的 **“先进后出” 容器 **，所有启动的 Activity 都会按 “入栈→栈顶运行→出栈销毁” 的规则管理：

  • 启动新 Activity → 入栈，成为栈顶（可交互）；

  • 按返回键 → 栈顶 Activity 出栈销毁，下一个 Activity 成为新栈顶；

  • 一个 APP 通常对应一个 Task 栈（singleInstance 模式除外）。

2. 教材核心定义

启动模式的本质是修改 Activity 入栈 / 复用的规则，通过控制栈内实例的创建 / 复用，实现不同的页面跳转逻辑。

二、4 种核心启动模式（教材必掌握）

1. Standard（标准模式）

（1）核心规则

  • 官方定义：默认启动模式，每次启动 Activity 都会创建新实例，无论栈中是否已有该 Activity 实例；

  • 通俗理解：“来一个建一个”，每次跳转都新建页面，栈中可存在多个相同 Activity 实例。

（2）核心行为

示例：MainActivity（栈底）→ 启动 MainActivity → 栈结构变为：MainActivity（底）→ MainActivity（顶）。

（3）应用场景

绝大多数普通页面（如列表页、详情页），需要多次创建的场景（如微信聊天页，每次点开新聊天都是新实例）。

（4）配置方式（默认无需配置，手动配置如下）

2. SingleTop（栈顶复用模式）

（1）核心规则

  • 官方定义：启动 Activity 时，仅当该 Activity 处于栈顶时复用实例，否则创建新实例；

  • 通俗理解：“栈顶有就用，没有就新建”，避免栈顶重复创建相同 Activity。

（2）核心行为

  • 场景 1：栈结构「A→B→C」，启动 C → 复用栈顶的 C，不新建，触发 onNewIntent() 方法；

  • 场景 2：栈结构「A→B→C」，启动 B → B 不在栈顶，新建 B，栈结构变为「A→B→C→B」。

（3）应用场景

接收通知跳转的页面（如微信通知栏点击进入聊天页，避免栈顶重复创建）、搜索页（多次点击搜索按钮不重复新建）。

（4）配置方式

3. SingleTask（栈内复用模式）

（1）核心规则

  • 官方定义：启动 Activity 时，整个栈中仅保留一个该 Activity 实例，若栈中已有则：

    ① 复用该实例（触发 onNewIntent()）；

    ② 将该实例上方的所有 Activity 出栈销毁；

  • 通俗理解：“栈内唯一，清空上方”，保证整个栈中只有一个该 Activity 实例。

（2）核心行为

示例：栈结构「A→B→C→D」，启动 B → 复用栈中的 B，同时销毁 C、D，栈结构变为「A→B」。

（3）应用场景

APP 主页面（如微信首页、抖音首页），确保返回时直接回到主页面，清空中间页面；或需要唯一实例的核心页面（如购物车、个人中心）。

（4）配置方式

4. SingleInstance（单实例模式）

（1）核心规则

  • 官方定义：整个系统中仅存在一个该 Activity 实例，且该实例独占一个独立的 Task 栈；

  • 通俗理解：“全局唯一，独占栈”，跨 APP 跳转也复用同一个实例（如手机拨号页、系统设置页）。

（2）核心行为

  • 启动该 Activity → 系统新建一个独立 Task 栈，将实例放入该栈；

  • 其他 APP / 页面启动该 Activity → 跳转到这个独立栈，复用唯一实例。

（3）应用场景

系统级页面（如拨号、短信）、APP 中需要全局唯一的特殊页面（如微信的 “扫一扫”，无论从哪打开都是同一个实例）。

（4）配置方式

三、启动模式对比表（教材考点）

启动模式 实例数量 所属 Task 栈 核心行为 典型场景
Standard 可多个 应用默认栈 每次启动新建实例 普通详情页、列表页
SingleTop 可多个（非栈顶） 应用默认栈 栈顶复用，非栈顶新建 通知跳转页、搜索页
SingleTask 栈内唯一 应用默认栈 复用实例，清空上方 Activity 首页、个人中心
SingleInstance 全局唯一 独立 Task 栈 独占栈，全局复用 拨号页、扫一扫

四、实战注意事项（教材易错点）

1. 两种配置方式的优先级

  • 代码中通过 Intent.addFlags() 设置的启动模式 → 优先级高于清单文件配置；

  • 注意：singleInstance 仅能在清单文件中配置，无法通过 Intent 标记设置。

2. onNewIntent() 方法的使用

  • 复用 Activity 实例时（singleTop/singleTask），系统不会调用 onCreate()，而是调用 onNewIntent()；

  • 需在 onNewIntent() 中处理新 Intent 的数据（如更新页面内容）：

3. 常见误区

  • 认为 singleTask 是 “全局唯一”：仅当前 APP 的 Task 栈内唯一，并非系统全局；

  • 滥用 singleInstance：独立栈会导致返回逻辑复杂，非系统级页面尽量不用；

  • 忽略栈结构变化：singleTask 会销毁上方 Activity，需注意数据保存（如表单内容）。

五、核心总结（教材考点）

  1. 启动模式的核心是管理 Activity 栈的实例创建 / 复用规则，解决页面重复创建、返回栈混乱问题；

  2. 标准模式（standard）是默认值，按需选择：首页用 singleTask，栈顶复用用 singleTop，全局唯一用 singleInstance；

  3. 复用实例时需重写 onNewIntent() 处理新数据，避免页面数据不更新；

  4. 配置优先级：Intent 标记 > 清单文件配置。
