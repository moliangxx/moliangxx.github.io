Log的使用

Log

在 Android 开发中，Log 是调试和排查问题的核心工具

一、基本 Log 级别与用法

Android 的 Log 类（android.util.Log）提供了 5 种日志级别，按从详细到严重的顺序排列：

级别 方法 适用场景
Verbose Log.v() 最详细的日志，用于开发过程中的临时调试信息，发布版本建议关闭。
Debug Log.d() 调试信息，用于记录关键流程的执行状态、变量值等，开发阶段常用。
Info Log.i() 重要的业务流程信息，比如用户登录、支付成功等，发布版本也可以保留。
Warn Log.w() 警告信息，比如非致命的错误、不规范的输入等，需要关注但不影响核心功能。
Error Log.e() 错误信息，比如崩溃、接口请求失败等，必须修复的问题，会触发告警。

二、实用 Log 技巧

  1. 规范使用 TAG

  • 每个类定义一个静态 TAG 常量，用类名作为 TAG，方便在 Logcat 中按 TAG 过滤日志。

  • 避免硬编码字符串，减少拼写错误。

  1. Logcat 过滤日志

  • 在 Android Studio 的 Logcat 面板中，你可以通过 TAG、级别、包名 来精准过滤日志：

    • 按 TAG 过滤：输入 tag:MainActivity

    • 按级别过滤：选择 Debug 或 Error 等级别，只显示对应级别及更严重的日志

    • 按包名过滤：输入 package:com.example.my_firstproject

  1. 自定义日志工具（推荐）
  • 封装一个 LogUtils，可以统一控制日志开关，避免在发布版本输出敏感日志：
  • 使用时直接调用 LogUtils.d(TAG, "调试信息")，发布版本会自动关闭日志。
  1. 避免使用 System.out.println
  • System.out 输出的日志无法在 Logcat 中灵活过滤，且性能不如 Log 类，开发中建议统一用 Log。

三、注意事项

  • 敏感信息不要输出：日志中不要包含用户密码、手机号、银行卡号等敏感数据，避免泄露。

  • 控制日志量：频繁输出大量日志会影响性能，开发阶段用完的临时日志建议及时删除。

  • 崩溃日志捕获：对于线上应用，建议集成第三方崩溃收集工具（如 Firebase Crashlytics），结合 Log.e() 记录错误上下文。
