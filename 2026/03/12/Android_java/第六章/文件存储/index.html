文件存储

一、文件存储核心概念

文件存储是将数据以 二进制流 形式保存到设备存储介质（内存、SD 卡）的方式，适用于存储任意格式的数据（文本、图片、视频、二进制文件等）。

关键区分：内部存储 vs 外部存储

特性 内部存储（Internal Storage） 外部存储（External Storage）
存储位置 应用私有目录（/data/data/包名/files/） 公共目录（如 /storage/emulated/0/DCIM/）或应用私有外部目录（/storage/emulated/0/Android/data/包名/files/）
访问权限 仅当前应用可访问，其他应用无权限 公共目录：所有应用可访问（需动态权限）；私有外部目录：仅当前应用可访问（无需动态权限）
数据安全性 应用卸载后数据自动删除，安全 公共目录：数据永久保留（卸载应用不删除）；私有外部目录：应用卸载后数据删除
存储容量 通常较小（受系统内存限制） 容量较大（依赖 SD 卡 / 设备存储）
适用场景 小体积、私密数据（如用户配置、缓存文件） 大体积、公开 / 半公开数据（如图片、视频、下载文件）

注意：Android 10（API 29）后引入

分区存储（Scoped Storage）

，外部存储的公共目录访问受限，推荐使用 MediaStore 或应用私有外部目录存储数据。

二、内部存储（Internal Storage）使用方法

内部存储是应用的 “私有文件夹”，无需权限即可读写，数据安全且随应用卸载删除，适合存储小体积私密数据（如用户偏好设置、文本日志）。

1. 核心 API

  • 获取内部存储根目录：getFilesDir() → 路径：/data/data/包名/files/（文件直接存放在此）

  • 获取内部存储缓存目录：getCacheDir() → 路径：/data/data/包名/cache/（存放缓存文件，系统低内存时可能自动清理）

三、外部存储（External Storage）使用方法

外部存储容量大，适合存储大体积数据，但访问规则在 Android 10 后有较大变化，需区分 应用私有外部目录 和 公共目录。

1. 外部存储分类及访问权限

存储类型 路径示例 访问权限 适用场景
应用私有外部目录 /storage/emulated/0/Android/data/包名/files/ 无需动态权限（Android 4.4+） 应用专属的大体积数据（如下载的图片、缓存视频）
公共目录（如 DCIM、Download） /storage/emulated/0/DCIM/、/storage/emulated/0/Download/ Android 10 前需 WRITE_EXTERNAL_STORAGE 动态权限；Android 10+ 需用 MediaStore 或请求 MANAGE_EXTERNAL_STORAGE 权限 公开数据（如用户拍摄的照片、下载的公共文件）

2. 应用私有外部目录（推荐，无权限困扰）

核心 API

  • 获取私有外部存储根目录：getExternalFilesDir(String type) → 类型参数可选（如 Environment.DIRECTORY_PICTURES 表示图片目录，null 表示根目录）

  • 获取私有外部缓存目录：getExternalCacheDir() → 路径：/storage/emulated/0/Android/data/包名/cache/（缓存文件，卸载应用删除）

四、文件存储避坑指南

  1. 权限适配：

  • Android 6.0（API 23）及以上，外部存储读写需动态申请权限（WRITE_EXTERNAL_STORAGE/READ_EXTERNAL_STORAGE）。

  • Android 10+ 优先使用应用私有外部目录或 MediaStore，避免申请 MANAGE_EXTERNAL_STORAGE 权限（需应用商店审核）。

  1. 存储状态检查：
  • 操作外部存储前必须检查存储状态（isExternalStorageWritable()/isExternalStorageReadable()），避免存储未挂载（如 SD 卡拔出）导致崩溃。
  1. 流关闭：
  • 所有文件流（FileInputStream/FileOutputStream）必须在 finally 中关闭，避免资源泄漏和文件损坏。
  1. 文件名规范：
  • 文件名避免特殊字符（如 `:/*?”），推荐使用字母、数字、下划线，确保跨设备兼容性。
  1. 文件大小限制：
  • 内部存储容量有限，避免存储大文件（如超过 100MB），大文件优先用外部存储。
  1. 数据备份：
  • 内部存储和应用私有外部目录的数据会随应用卸载删除，重要数据需备份到公共目录或云端。
  1. 中文乱码处理：
  • 读写文本文件时指定编码（如 UTF-8），避免因默认编码导致中文乱码。

五、文件存储与其他持久化方式对比

持久化方式 适用场景 优势 劣势
文件存储 任意格式数据（文本、图片、视频） 灵活通用、支持大文件 需手动管理文件、查询数据效率低
SharedPreferences 键值对配置（如用户设置） 简单易用、自动序列化 仅支持基本数据类型、不适合大量数据
SQLite 数据库 结构化数据（如用户列表、商品信息） 支持查询、事务、索引 操作复杂、适合大量结构化数据
Room 数据库 结构化数据（SQLite 封装） 生命周期感知、编译时校验 依赖 Room 库、学习成本略高
