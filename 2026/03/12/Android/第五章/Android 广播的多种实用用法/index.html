2. 跨组件通信（Activity ↔ Fragment ↔ Service）

  • Activity → Fragment：发送本地广播，Fragment 中注册接收，实现数据传递；

  • Service → Activity：后台任务完成后发送广播，通知 UI 更新（如音乐播放进度、下载完成）。

四、Android 12+ 最佳实践（避坑指南）

  1. 显式 Intent 优先：发送广播时指定包名 / 组件类，避免 exported 警告和包可见性问题；

  2. 本地广播推荐：本应用内通信优先用 LocalBroadcastManager，无需 exported，更安全；

  3. 权限控制：静态注册广播时，android:exported 设为 false，仅在需要跨应用时设为 true；

  4. 生命周期管理：动态注册广播后必须在 onDestroy() 中取消注册，避免内存泄漏。

✅ 总结

用法类型 核心特点 适用场景
标准广播 异步、无顺序，所有接收器同时收到 本应用内简单通知
有序广播 同步、有优先级，可截断 需要顺序处理、结果返回的场景
本地广播 仅本应用内，安全高效 组件间通信、UI 更新
粘性广播 广播留存，新注册接收器可收到 状态同步（如网络、电量）
系统广播 系统发出，监听设备状态 开机启动、网络变化、电量低等
