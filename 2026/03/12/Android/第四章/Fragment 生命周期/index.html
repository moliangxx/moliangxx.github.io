Fragment 生命周期

一、Fragment 核心生命周期状态

Fragment 的生命周期分为 5 个核心状态，对应不同的存在阶段，所有回调方法都围绕这些状态切换触发：

状态 说明 对应核心回调
运行状态（Resumed） Fragment 可见且与用户交互（关联的 Activity 也处于运行状态） onResume()
暂停状态（Paused） Fragment 可见但不可交互（比如 Activity 被半透明弹窗覆盖） onPause()
停止状态（Stopped） Fragment 不可见（Activity 停止或 Fragment 被替换） onStop()
销毁状态（Destroyed） Fragment 布局被销毁（但可能仍与 Activity 关联）或完全销毁 onDestroyView() / onDestroy() / onDetach()
初始化状态（Initialized） Fragment 实例创建完成，但未加载布局 onCreate()

二、Fragment 完整生命周期回调（按执行顺序）

以下是 Fragment 从创建到销毁的所有回调方法，结合 Java 代码示例和《第一行代码》的重点说明：

1. 初始化阶段：Fragment 实例创建 → 布局加载

回调方法 作用 Java 代码示例
onAttach(Context context) Fragment 与 Activity 关联时调用（获取 Activity 引用） java @Override public void onAttach(Context context) { super.onAttach(context); // 此时可通过 context 获取 Activity，或绑定通信接口 listener = (OnFragmentInteractionListener) context; }
onCreate(Bundle savedInstanceState) Fragment 实例创建时调用（初始化数据，不受布局销毁影响） java @Override public void onCreate(Bundle savedInstanceState) { super.onCreate(savedInstanceState); // 初始化全局数据（如从 Activity 接收参数） String data = getArguments().getString("key"); }
onCreateView(LayoutInflater inflater, ViewGroup container, Bundle savedInstanceState) 加载 Fragment 布局（核心方法，返回布局 View） java @Override public View onCreateView(LayoutInflater inflater, ViewGroup container, Bundle savedInstanceState) { // 加载布局，container 是父容器，false 表示不立即添加 View view = inflater.inflate(R.layout.fragment_first, container, false); // 绑定布局内控件 tvTitle = view.findViewById(R.id.tv_title); return view; }
onActivityCreated(Bundle savedInstanceState) 关联的 Activity 的 onCreate() 执行完后调用（可操作 Activity 控件） java @Override public void onActivityCreated(Bundle savedInstanceState) { super.onActivityCreated(savedInstanceState); // 此时 Activity 已初始化完成，可通过 getActivity() 获取 Activity 控件 TextView activityTv = getActivity().findViewById(R.id.activity_tv); }

2. 运行阶段：Fragment 可见 → 交互

回调方法 作用 Java 代码示例
onStart() Fragment 可见时调用（Activity 进入 onStart() 后触发） java @Override public void onStart() { super.onStart(); // 执行可见状态的逻辑（如启动动画、刷新数据） tvTitle.setText("Fragment 已可见"); }
onResume() Fragment 可与用户交互时调用（Activity 进入 onResume() 后触发） java @Override public void onResume() { super.onResume(); // 执行交互相关逻辑（如注册监听、启动定时器） timer.start(); }

3. 暂停 / 停止阶段：Fragment 不可交互 → 不可见

回调方法 作用 Java 代码示例
onPause() Fragment 不可交互但可见时调用（如 Activity 被弹窗覆盖） java @Override public void onPause() { super.onPause(); // 暂停交互逻辑（如暂停动画、保存临时数据） timer.pause(); }
onStop() Fragment 完全不可见时调用（如 Activity 进入后台、Fragment 被替换） java @Override public void onStop() { super.onStop(); // 停止耗时操作（如关闭网络请求、注销广播） httpClient.cancel(); }

4. 销毁阶段：布局销毁 → 实例销毁

回调方法 作用 Java 代码示例
onDestroyView() Fragment 布局被销毁时调用（释放布局内控件引用） java @Override public void onDestroyView() { super.onDestroyView(); // 清空控件引用，避免内存泄漏 tvTitle = null; view = null; }
onDestroy() Fragment 实例销毁时调用（释放全局数据、资源） java @Override public void onDestroy() { super.onDestroy(); // 释放全局资源（如取消定时器、销毁集合） timer.cancel(); dataList.clear(); }
onDetach() Fragment 与 Activity 解除关联时调用（清空 Activity 引用） java @Override public void onDetach() { super.onDetach(); // 清空接口引用，避免内存泄漏 listener = null; }

三、Fragment 与 Activity 生命周期的关联（关键！）

Fragment 依附于 Activity，其生命周期会跟随 Activity 变化，但存在自己的独立回调。《第一行代码》中用表格清晰展示了对应关系（Java 场景下完全一致）：

Activity 生命周期回调 对应的 Fragment 回调
onCreate() Fragment 的 onAttach() → onCreate() → onCreateView() → onActivityCreated()
onStart() Fragment 的 onStart()
onResume() Fragment 的 onResume()
onPause() Fragment 的 onPause()
onStop() Fragment 的 onStop()
onDestroy() Fragment 的 onDestroyView() → onDestroy() → onDetach()

注意：如果 Activity 被销毁（如旋转屏幕），Fragment 会先执行

onDestroyView()

→

onDestroy()

→

onDetach()

，再重新执行初始化流程（

onAttach()

开始）；若通过

addToBackStack()

将 Fragment 加入返回栈，替换时只会执行

onDestroyView()

，返回时重新执行

onCreateView()

→

onActivityCreated()

等。

四、生命周期关键场景示例（Java 版）

场景 1：Fragment 被动态替换（加入返回栈）

  • 原 Fragment 生命周期：onPause() → onStop() → onDestroyView()（不执行 onDestroy () 和 onDetach ()）

  • 返回时原 Fragment 生命周期：onCreateView() → onActivityCreated() → onStart() → onResume()

场景 2：Activity 旋转屏幕（Fragment 重建）

  • 原 Fragment 生命周期：onPause() → onStop() → onDestroyView() → onDestroy() → onDetach()

  • 重建后 Fragment 生命周期：onAttach() → onCreate() → onCreateView() → onActivityCreated() → onStart() → onResume()
