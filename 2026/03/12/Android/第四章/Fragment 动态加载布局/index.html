Fragment 动态加载布局

一、核心需求：为什么需要动态加载布局？

手机屏幕窄，适合 “单页显示”（点击列表跳详情）；平板屏幕宽，适合 “双页显示”（左侧列表 + 右侧详情）。通过 限定符 自动匹配布局，结合 Fragment 动态加载，可实现一套代码适配两种设备，无需单独开发。

二、关键技术：限定符（Qualifier）的使用

Android 允许在 res 目录下创建带 限定符 的布局文件夹（如 layout-sw600dp），系统会根据设备特性（屏幕尺寸、方向等）自动加载对应文件夹的布局文件。

1. 常用限定符（《第一行代码》重点）

限定符 含义 适用场景
sw>dp 最小屏幕宽度 ≥ N dp（优先推荐） 区分手机（sw0dp）和平板（sw≥600dp）
w<N>dp 屏幕宽度 ≥ N dp 按屏幕宽度适配
h<N>dp 屏幕高度 ≥ N dp 按屏幕高度适配
land 横屏 区分横竖屏布局
port 竖屏 （默认，可省略）

说明：

sw600dp

表示 “最小屏幕宽度至少 600dp”，是 Google 推荐的平板与手机的分界值（大部分平板最小宽度 ≥600dp，手机 <600dp）。

2. 文件夹命名规范

  • 手机布局（默认）：res/layout/（无限定符）

  • 平板布局（最小宽度 ≥600dp）：res/layout-sw600dp/（限定符 sw600dp）

  • 横屏布局：res/layout-land/（限定符 land）

四、核心原理总结

  1. 限定符自动匹配布局：设备运行时，系统会优先查找带限定符的布局文件夹（如平板找 layout-sw600dp），找不到则用默认 layout 文件夹的布局。

  2. 双页 / 单页判断逻辑：通过 findViewById(``R.id``.detail_fragment_container) 是否为 null，判断是否为平板（双页模式）。

  3. Fragment 数据传递：用 Bundle 存储数据，通过 setArguments(bundle) 传递给目标 Fragment，避免直接 new 实例传参（防止 Fragment 重建时数据丢失）。

  4. 动态加载核心：平板模式下，通过 FragmentTransaction.replace() 动态替换详情容器的 Fragment；手机模式下，跳转 Activity 加载详情 Fragment。

五、拓展：其他限定符的使用场景

1. 横竖屏适配（land/port 限定符）

  • 横屏布局文件夹：res/layout-land/

  • 竖屏布局文件夹：res/layout-port/（默认可省略）

  • 用途：比如视频播放页面，横屏显示播放器，竖屏显示播放器 + 评论区。

2. 屏幕密度适配（hdpi/xhdpi 等）

  • 图片资源文件夹：res/drawable-hdpi/、res/drawable-xhdpi/

  • 用途：不同密度屏幕加载对应分辨率的图片，避免模糊或拉伸。
