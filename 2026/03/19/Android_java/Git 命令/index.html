Android：Git 命令

🎯 Git 命令学习清单（新手→进阶）

我按「新手必学（80% 场景够用）」「进阶用法（解决复杂问题）」「避坑技巧」三类整理，结合你的「推箱子游戏开发」场景举例，每个命令都标注「作用 + 使用场景 + 示例」，新手能直接抄用。

一、新手必学核心命令（90% 日常开发够用）

1. 仓库初始化 / 克隆（项目起步）

命令 作用 示例（你的推箱子项目）
git init 在本地创建空的 Git 仓库 cd 你的推箱子项目目录git init
git clone <仓库地址> 克隆远程仓库到本地（比如从 Gitee 拉项目） git clone https://gitee.com/你的账号/pushing-box.git

2. 文件状态 / 暂存（提交前准备）

命令 作用 示例
git status 查看文件状态（未追踪 / 已修改 / 已暂存） git status（看 RankingContentProvider.java 是否被追踪）
git add <文件名> 将指定文件加入暂存区（精准提交） git add app/src/main/java/.../RankingContentProvider.java
git add . 将所有修改的文件加入暂存区（批量提交） git add .（提交所有改的代码）
git rm --cached <文件名> 取消暂存（误加文件时用） git rm --cached 无用的测试文件.txt

3. 提交 / 查看记录（核心操作）

命令 作用 示例
git commit -m "提交信息" 提交暂存区文件到本地仓库（必须写清晰信息） git commit -m "fix: 移除 ContentProvider 中的 db close 操作"
git commit --amend 修改最后一次提交（比如补写提交信息） 提交后发现信息写错：git commit --amend -m "fix: 修复 ContentProvider 数据库崩溃问题"
git log 查看详细提交记录（作者 / 时间 / 修改内容） git log
git log --oneline 简洁版提交记录（只看 commit id + 信息） git log --oneline（快速查历史）

4. 远程同步（推 / 拉代码）

命令 作用 示例
git push <远程名> <分支名> 推送本地提交到远程仓库 git push origin main（推到主分支）
git pull <远程名> <分支名> 拉取远程最新代码并合并（同步队友修改） git pull origin main（解决冲突前先拉）
git remote -v 查看远程仓库地址（确认是否连对 Gitee/GitHub） git remote -v
git remote add origin <仓库地址> 绑定本地仓库到远程（首次推送时用） git remote add origin https://gitee.com/你的账号/pushing-box.git

5. 分支基础（避免改乱主分支）

命令 作用 示例（推箱子游戏）
git branch 查看所有分支（* 表示当前分支） git branch
git branch <分支名> 创建新分支（比如开发新功能） git branch feature/achievement（成就系统分支）
git checkout <分支名> 切换分支 git checkout feature/achievement（切到成就分支开发）
git checkout -b <分支名> 创建并切换分支（常用快捷方式） git checkout -b bugfix/db-crash（修复数据库崩溃分支）

二、进阶用法（解决复杂场景）

1. 代码回滚 / 撤销（救急必备）

命令 作用 适用场景 示例
git reset --soft HEAD^ 撤回最后一次提交，保留代码（最安全） 提交后发现漏改代码 git reset --soft HEAD^（撤回后代码还在，改完重新提交）
git reset --hard HEAD^ 撤回最后一次提交，删除代码（慎用） 提交了错误代码，想彻底删掉 git reset --hard HEAD^（代码会被删，确认无误再用）
git checkout -- <文件名> 撤销文件的本地修改（恢复到上次提交状态） 改乱了 RankingDBHelper.java，想还原 git checkout -- app/src/main/.../RankingDBHelper.java
git revert <commit id> 撤销指定提交（保留提交记录，适合已推送的代码） 远程分支上的错误提交，不想删记录 git revert 8f179a6（8f179a6 是 commit id，从 git log 查）

2. 分支高级操作（多人协作）

命令 作用 示例
git merge <分支名> 将指定分支合并到当前分支（比如功能完成合入主分支） 切到 main 分支后：git merge feature/achievement
git branch -d <分支名> 删除本地分支（功能合并后清理） git branch -d feature/achievement
git push origin --delete <分支名> 删除远程分支 git push origin --delete feature/achievement
git stash 暂存未提交的修改（临时切分支时用） 正在改代码，要切分支修 bug：git stash（暂存修改）切分支修完后切回来：git stash pop（恢复暂存的代码）

3. 冲突解决（多人协作必遇）

命令 作用 步骤
git mergetool 打开可视化冲突解决工具（比手动改清晰） 1. git pull origin main（拉代码触发冲突）2. git mergetool（打开工具选保留哪版代码）3. git add .（标记冲突已解决）4. git commit -m "fix: 解决 ContentProvider 冲突"
git diff 查看文件修改差异（定位冲突点） git diff app/src/main/.../RankingContentProvider.java（看冲突的具体代码）

4. 标签管理（版本发布）

命令 作用 示例（推箱子游戏 v1.0 发布）
git tag v1.0 创建标签（标记发布版本） git tag v1.0
git push origin v1.0 推送标签到远程 git push origin v1.0
git tag -d v1.0 删除本地标签 git tag -d v1.0

三、新手避坑技巧（关键提醒）

  1. 提交信息要规范：别写「改了代码」「修复 bug」，按「类型：描述」写，比如：

  • feat: 添加排行榜提交功能（新功能）

  • fix: 修复 ContentProvider 数据库崩溃（修复 bug）

  • docs: 更新 README 说明（文档修改）

  1. 不要直接改 main 分支：新功能 / 修 bug 都建分支，合并前先测试；

  2. 提交前先 git status：确认只提交需要的文件，避免提交 IDE 配置文件（比如 .idea/）；

  3. 慎用 git reset --hard：会彻底删除代码，执行前先确认；

✅ 总结

阶段 核心命令 学习优先级
新手 init/clone → add → commit → push/pull → branch/checkout 最高（先掌握，能完成基础开发）
进阶 reset/revert → merge → stash → mergetool 次高（解决冲突、回滚、分支管理）
高阶 tag → rebase → cherry-pick 按需学（发布版本、精细化分支操作）
