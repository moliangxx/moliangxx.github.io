从灵江项目学 Android：面试向系列索引

这套文章不写”教科书式科普”，每篇都对照灵江项目 d:\AndroidProject\LingJiang 里真实存在的代码（下文路径均相对 app/src/main/java/com/lingjiang/）。目的是：面试时能说出”我在项目里就是这么用的、为什么这么用、踩过什么坑”，而不是背定义。

系列文章

序号 文章 主要考点
1 《策略模式：从灵江项目的类型分发说起》 枚举/when 分发、DataShowFragment 的 specOf 单点映射、HomeFeedAdapter 槽位策略、策略 vs 工厂、开闭原则边界
2 《适配器的几种写法：从灵江的 Adapter 说起》 多 ViewType、手写 DiffUtil、ListAdapter/ConcatAdapter/payload 取舍、复用导致的状态错乱、异步图片串位
3 《MVVM 与其他架构：灵江的 ViewModel 到底承担了什么》 MVC/MVP/MVVM/MVI 数据流向、单向数据流、StateFlow/LiveData/SharedFlow、repeatOnLifecycle、viewLifecycleOwner、SavedStateHandle
4 《注解的运用：编译期生成代码，还是运行时反射？》 元注解与保留策略、KAPT vs KSP、Room/Retrofit 注解的真实生效方式、@Volatile、@JvmStatic/@JvmOverloads、@SuppressLint
5 《密封类（sealed class / sealed interface）：从灵江的联合模型说起》 sealed 的编译期穷尽、子类限制、与枚举/抽象类的取舍、序列化与混淆
6 《枚举、const val、普通 val 与 @IntDef：灵江项目的四种"常量"取舍》 四种常量的编译产物、类型安全、when 穷尽、ordinal 持久化陷阱、values() vs entries
7 《协程与 Flow：灵江项目里的搜索防抖、聊天发送与 Room 订阅》 挂起不等于切线程、结构化并发、StateFlow/SharedFlow、取消与异常、collectLatest 的真实坑
8 《数据类与存储策略：灵江的 data class、单表/拆表与 Room 幂等》 data class 的 equals/hashCode/toString/copy/componentN、单表与拆表取舍、字段冗余、userId+type+refId 幂等计分与竞态、DB_VERSION 与 Migration

8 篇已全部落地，链接与标题均已按实际文章核对。系列持续更新。

建议阅读顺序

  1. 先读第 5 篇（sealed）：它是第 1、2 篇的前置知识——灵江的 HomeFeedNode、SearchItem、ChatAdapter.Row 全是 sealed 联合模型；
  2. 再读第 1 篇（策略）：理解”类型 → 行为”的分发为什么集中到 specOf、getItemViewType、dataFlow 这几个点；
  3. 第 2 篇（适配器）：把策略落到 RecyclerView 的具体写法，重点看 DiffUtil 的两个回调和复用清理；
  4. 第 3 篇（MVVM）：把前面的数据流串起来，理解 Flow → ViewModel → UI 的单向数据流；
  5. 第 4 篇（注解）：解释前面出现的 @Entity、@Query、@GET、@Volatile 到底谁在处理、什么时候处理；
  6. 第 6~8 篇：补齐常量方案、协程/Flow、data class 与 Room 存储策略，避免面试时被”展开成普通写法”或”为什么这么建表”问住。

代码对照约定

  • 所有代码路径均相对 app/src/main/java/com/lingjiang/，例如 main/home/HomeFeedAdapter.kt；
  • 标注”通用示例”的代码表示灵江项目里没有对应实现（如 ListAdapter、ConcatAdapter、@IntDef、@Keep），是为了讲清概念而给的最小示例，不对应任何伪造文件路径；
  • 灵江项目里不存在的类（如 MainViewModel、BleDataViewModel，它们属于 LingYuan 工程）不会出现在正文的”项目实例”里，遇到命名混淆会在文中明确说明。

一句话总结

这 8 篇的共同目标只有一个：把”我记得这个概念”换成”我在灵江的哪一行代码里用过它、为什么这么写、出过什么问题”——面试时，后者才是可信的答案。
