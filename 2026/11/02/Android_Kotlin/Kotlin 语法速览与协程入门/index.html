Kotlin 语法速览与协程入门

如果你已经写过 Android 的 Java 代码，Kotlin 不是“另一门语言”，而是把常见的样板代码折叠起来的工具。这篇笔记按“写业务时最常用”的顺序整理，最后落到协程。

一、空安全：把 NPE 挡在编译期

写法 含义 建议
String? 可以为 null 网络、数据库字段默认用它
String 一定不为 null 内部确定值用它
?. 安全调用 首选
!! 强制非空 只在确定不会为 null 时用

一个经验：!! 出现在业务代码里，通常意味着“这里应该有兜底逻辑”。

二、val / var、数据类与解构

data class 自动生成 equals / hashCode / toString / copy，非常适合做 UI 状态和网络实体。

注意：copy() 是浅拷贝，内部集合仍指向同一个对象。

三、扩展函数与作用域函数

常用作用域函数的选择：

函数 上下文对象 返回值 典型场景
let it lambda 结果 空安全链式调用
run this lambda 结果 配置对象并返回结果
apply this 对象本身 初始化 View / Builder
also it 对象本身 日志、副作用
with this lambda 结果 对同一对象多次操作

四、Lambda、高阶函数与集合操作

Android 里最常见的组合是 filter + map + firstOrNull。如果链路很长，优先考虑 Sequence，避免每一步都创建新集合：

五、协程：先把“回调地狱”拆掉

5.1 三个基础构件

  • suspend：可挂起函数，只能在协程或其他 suspend 函数中调用。
  • CoroutineScope：协程的生命周期边界。
  • Dispatchers：决定在哪个线程执行。

5.2 在 ViewModel 中使用

viewModelScope 会跟随 ViewModel 一起取消，避免页面销毁后继续回写 UI。

5.3 并发：async 与 await

coroutineScope 保证任一子任务失败时，整个作用域取消，不会留下半成品状态。

5.4 Flow：持续的数据流

需求 建议
一次性请求 suspend 函数
数据库变化 / 轮询 Flow
UI 状态 StateFlow
多个上游合并 combine / merge

六、迁移时的几个坑

  1. 平台类型：Java 返回值可能是 String!，接收时主动声明可空或非空。
  2. SAM 转换：Java 接口可以用 lambda，但 Kotlin 接口需要 object : 或 fun interface。
  3. 默认参数：Java 调用 Kotlin 默认参数时要用 @JvmOverloads 生成重载。
  4. 可空集合：List<String>? 与 List<String?> 是两件事。

七、小结

Kotlin 的学习顺序建议是：

  1. 空安全与 val/var
  2. 数据类、扩展函数
  3. Lambda + 集合
  4. suspend 与 viewModelScope
  5. Flow 与 StateFlow

把这五步走完，再去看 Compose 和 MVVM，代码会顺很多。
