ESP32-S3 联网实战：Wi-Fi、MQTT 与 OTA

点灯只是开始。真正做项目时，设备要能联网、上报、远程升级，还要在断网时自己恢复。这篇整理一套能直接用的骨架。

一、Wi-Fi：自动重连比连上更重要

工程建议：

  • 用 WiFi.setAutoReconnect(true) + WiFi.persistent(true)。
  • Wi-Fi 事件回调里做状态机，不要只靠 delay 轮询。
  • 密码不要硬编码，量产时放 NVS 或配网流程。
  • 信号弱时把发射功率调到 WIFI_POWER_8_5dBm，省电且稳定。

注意事项：

  1. 分区表必须包含两个 APP 分区（app0 / app1），否则无法回滚。
  2. 升级过程中断电可能变砖，建议加看门狗与“升级成功标记”。
  3. 远程 OTA 必须用 HTTPS 并校验 CA，不要用 setInsecure() 上生产。
  4. 先用小固件验证，再替换整机固件。

六、功耗与稳定性建议

场景 建议
电池供电 用 light sleep，Wi-Fi 保持连接
长期在线 关闭 debug 日志，降低 CPU 频率至 160 MHz
室内传感器 每 5 分钟上报一次，其余时间休眠
摄像头 按需启动，采完即关
看门狗 启用 esp_task_wdt，避免任务卡死

七、常见问题

  1. MQTT 频繁掉线：检查 keepAlive 与 mqtt.loop() 是否被长任务阻塞。
  2. OTA 卡在 0%：先确认 URL 可访问、证书时间正确、分区表够大。
  3. Wi-Fi 连上但无网：检查 DNS 与路由器是否隔离了设备。
  4. 内存不足重启：TLS + JSON + 大 buffer 很吃 RAM，必要时用 PSRAM。

八、小结

联网部分的核心不是“连上”，而是断了能自己回来：

  • Wi-Fi 用事件 + 自动重连；
  • MQTT 用 retained 状态 + QoS 1；
  • OTA 用双分区 + HTTPS；
  • 主循环不要被阻塞。

做到这四点，设备才具备上线的基本条件。
