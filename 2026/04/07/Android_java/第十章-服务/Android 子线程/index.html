Android 子线程运用

Android 规定：所有耗时操作必须放在子线程（网络请求、数据库读写、文件读写、复杂计算），所有 UI 更新必须在主线程（也叫 UI 线程）。

如果在主线程做耗时操作，会触发ANR（应用无响应） 崩溃；在子线程直接更新 UI，会直接报错。

一、最常用的 4 种子线程方案（按推荐度排序）

1. 官方首选：Coroutine 协程（最简单、最安全）

Kotlin 官方推荐，代码简洁，自动管理生命周期，不会内存泄漏。

基础用法

核心优势

  • 不用手动切线程，withContext 自动切子线程

  • lifecycleScope 会在页面销毁时自动取消任务，无内存泄漏

  • 代码扁平化，无回调嵌套

2. 传统方案：Thread + Handler（老项目常用）

Java/Kotlin 通用，最基础的线程用法，适合理解原理。

简化写法（Java 也能用）

⚠️ 缺点：手动管理线程，容易内存泄漏，不推荐新项目大量使用。

3. 异步任务：AsyncTask（已废弃，仅老项目兼容）

Android 早期封装的异步类，Android 11 已废弃，不要在新项目使用。

4. 线程池：ThreadPoolExecutor（大量并发任务）

适合批量、多次、频繁的异步任务（如多文件下载、批量接口请求），避免频繁创建销毁线程。

二、核心规则（必须记住）

  1. 主线程：只能做 UI 操作，不能做耗时操作（>500ms 就危险）

  2. 子线程：只能做耗时操作，不能直接更新 UI

  3. 切线程工具：

  • Kotlin：lifecycleScope + withContext(``Dispatchers.IO``)

  • Java：Thread + runOnUiThread

三、实战示例：网络请求（标准写法）

四、常见错误

  1. 子线程更新 UI → 崩溃

  2. 主线程网络请求 → 崩溃（Android 9+ 禁止）

  3. 线程未关闭 → 内存泄漏（用协程 lifecycleScope 可避免）
